ELI5+ · 项目解读

这个项目是干嘛的：
一个会自己查资料、自己开工具的值班助手

SuperBizAgent 是一个跑在浏览器里的运维助手。你把一句话或者一条告警丢进去，它不会立刻硬答， 而是先决定要查什么（拆成几个步骤），再去调工具取证（拉监控曲线、搜日志、翻处理手册）， 最后给你一份带证据的结论。如果中途发现证据不够，它会自己改计划。

FastAPI · :9900 LangGraph 状态机 qwen-max Milvus 向量库 MCP 工具协议
01

先看骨架：它不是「问答机器人」，是「会取证的问答机器人」 四段式 —— 收到输入、拆步骤、调工具、出结论，中间还有一条回头的线

普通问答机器人是「你问它背答案」。这个项目多了一整套动作：决定去查什么 → 真的去查 → 判断查到的东西够不够。 它背后是三个各管一段的 LLM 节点，串在一张状态图上循环跑，这就是 Plan-Execute-Replan。

02

它填的是哪个坑：值班时那条又长又重复的手工链 每一步都不难，难的是「串起来」和「每次都要重来一遍」

告警一响，值班的人要接连做完一串动作：开监控看曲线 → 开日志平台按时间窗搜关键词 → 翻 wiki 找对应 SOP → 手动拼出结论发到群里。 每一步技术上都很简单，但换个人、换个时间，路径和判断标准就飘了。

打个比方（类比）：像一个刚入职但很守规矩的初级值班员。他不懂业务，但手里有一本操作手册， 照着「先看监控、再看日志、最后对案例」的流程一步步做，每做一步会把查到的东西记在小本子上。

类比在哪里不成立：他不会真的「理解」业务，也不知道这个系统长什么样。他只能问工具，而工具给什么，他就信什么。 如果工具数据本身是假的（这个项目的工具数据确实是模拟的，见第 07 节），他会一本正经地分析一堆编出来的数字。
03

两个入口，共用同一个大脑 左边「问它怎么处理」，右边「让它自己去查」

打开 localhost:9900，界面上是一个聊天框，下拉里能选快速问答或流式对话（两者的区别只是「一次性返回」还是「边生成边吐字」， 背后是同一套 RAG Agent）。另外还有一个独立的诊断入口，走的是完全不同的 Plan-Execute-Replan 流程。

04

核心机制：那个循环到底在转什么 下面这段是可以播的 —— 点「播放」看一次真实状态演进

整套循环只维护四个变量：input（原始任务）、plan（还没做的步骤队列）、 past_steps（做过的步骤和结果）、response（最终报告）。 每转一圈，队列少一项、历史多一项，直到 response 被填上就结束。

    规则 1

    8 步封顶

    已执行满 8 步，不管查到什么都强制写报告收尾，避免无限循环烧 token。

    规则 2

    跑够 5 步不准改计划

    已经查了 5 步还想 replan，会被直接拦下改成 respond —— 防止它反复推翻自己。

    规则 3

    新计划不能更长

    replan 出来的新步骤数超过剩余步骤数时会被截断，保证计划只会收缩，不会膨胀。

    这三条不是「智能」的一部分，恰恰相反 —— 它们是给 LLM 套的护栏，写在 replanner.py 里，是硬编码常量。说明作者被模型「聊着聊着就跑偏」坑过。

    05

    「手脚」从哪来：MCP 是个统一的工具插座 Agent 不关心日志系统是哪家厂商，只关心对面说不说 MCP

    MCP（Model Context Protocol）解决的事情很朴素：让大模型能以一种标准格式拿到「有哪些函数可调、参数长什么样」。 项目里起了两个本地 MCP 服务，Agent 启动时 get_tools() 一次性把它们的工具签名全拉过来，再交给模型去选。

    还有个细节值得一提：MCP 工具调用外面套了一层重试拦截器 —— 失败按指数退避重试 3 次，全失败就返回一段错误文本而不是抛异常。 这样单个工具挂掉不会让整个诊断流程崩掉，模型会看到「这个查询失败了」然后继续往下走。

    06

    知识怎么进库：一份 md 文档的四次变身 RAG 那三个字母，落地就是这条流水线

    aiops-docs/ 里放着 5 份故障处理手册（CPU 高、内存高、磁盘满、服务不可用、响应慢）。 上传时它们会被切块、向量化、塞进 Milvus；提问时再被「按意思」捞出来。

    07

    技术栈一张表 东西不多，但每条都选得很「教学向」

    层用了什么在这儿的实际作用
    Web 框架FastAPI + uvicorn单进程，一个 9900 端口同时伺服 API 和静态前端
    流式输出sse-starlette把每个 token 包装成 SSE 事件推给浏览器，所以能打字机式输出
    编排LangGraph把 planner / executor / replanner 连成带条件边的状态图
    模型ChatQwen · qwen-max拆计划、选工具、写结论，都是它在做（DashScope 接口）
    向量库Milvus + langchain-milvusDocker Compose 起的 standalone，数据落在 volumes/

    工具协议FastMCP + langchain-mcp-adapters两个本地 MCP 服务，通过 streamable-http 暴露工具

    前端原生 HTML/CSS/JSstatic/ 三个文件，无构建、无框架
    08

    必须知道的边界：它演示的是「流程」，不是「真实排障能力」 这几条如果不知道，会对这个项目产生完全错误的印象

    01

    日志和监控数据是程序编出来的

    cls_server.py 里的日志是按时间窗现生成的，monitor_server.py 的 CPU 曲线是一条「从 10% 指数爬到 95%」的公式加随机抖动。 两个文件里都没有任何网络请求，也没装腾讯云 SDK。所以它演示的是「拿到数据之后怎么分析」，而不是「怎么从真实系统里拿数据」。

    mcp_servers/README.md：「当前版本返回模拟数据，生产环境需配置真实 API」
    02

    会话记忆存在内存里

    用的 MemorySaver，不是 Redis 也不是数据库。进程一重启，所有历史对话全丢；起两个实例也不能共享会话。 另外消息超过 7 条会截断，只保留首条 system + 最近 6 条，问得太长它会「忘掉」开头。

    rag_agent_service.py · trim_messages_middleware / MemorySaver
    03

    上传只吃 txt 和 md，且没有解析层

    PDF、Word、Excel 全部拒收。也没有做表格/图片抽取，因为整个管线就是「读文本 → 切块 → 向量化」。 真实排障资料大量是截图和 PDF，这是明显的落地缺口。

    api/file.py · ALLOWED_EXTENSIONS = ["txt", "md"]
    04

    没有登录、没有鉴权、CORS 全开

    allow_origins=["*"]，接口裸奔。任何人都能调 /api/chat 烧你的 API key，也能直接上传文件。 只能在内网或本地演示环境跑，不能直接对外。

    app/main.py · CORSMiddleware
    05

    「智能」其实被三条硬编码规则牢牢框住

    8 步封顶、5 步禁 replan、新计划不许变长 —— 全是常量而不是配置。换句话说， 作者对模型自主性的信任度不高，宁可让它在证据不完美时收尾，也不允许它自由发挥。 这也意味着：想让它在更复杂的故障上跑得更深，得先改代码。

    agent/aiops/replanner.py · MAX_STEPS = 8
    06

    诊断任务本身是写死的一句话

    /api/aiops 不接收「你想诊断什么」，请求体里只有 session_id。 要诊断的具体内容和报告格式都硬编码在 aiops_service.diagnose() 里。 所以它不是「通用诊断平台」，而是「一个做得很完整的单场景 demo」。

    services/aiops_service.py · diagnose()
    一句话记住它

    它把「值班的套路」写成了代码：
    知识库给套路，MCP 给工具，Plan-Execute-Replan 给纪律。

    如果你要拿去答辩或者做二次开发，价值不在「它能诊断 CPU 高」——这部分数据是假的。 价值在它把一条完整的 Agent 工程链路跑通了：流式输出、工具协议、向量检索、状态机循环、护栏设计，每一块都有能指着讲的代码位置。

    要演示流程现在就能跑：起 Milvus、两个 MCP 服务、FastAPI，点诊断看它一圈圈转
    要接真实数据只需替换两个 MCP server 的内部实现，上层 Agent 一行都不用改 —— 这正是 MCP 的价值
    要上生产得补：鉴权、会话持久化、文档解析、工具白名单、可观测性
    解读基于仓库实读：app/（main / api / services / agent / tools / core）、mcp_servers/、aiops-docs/、README.md、mcp_servers/README.md、pyproject.toml。 「模拟数据」与「流程设计」的判断都标注了对应文件位置，可自行核对；未验证的内容未写入。
